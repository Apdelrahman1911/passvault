# PassVault encrypted backup format

This document describes the format implemented by
`core/database/.../backup/VaultBackupService.kt`. It is not a roadmap.

## Version 1 container

The file extension used by the UI is `.pvault`. The file is UTF-8 JSON containing one authenticated-encryption
envelope:

```json
{
  "formatVersion": 1,
  "kdfAlgorithm": "Argon2id",
  "argon2OpsLimit": 3,
  "argon2MemLimit": 67108864,
  "argon2Parallelism": 1,
  "salt": "<base64, 16 bytes>",
  "nonce": "<base64, 24 bytes>",
  "ciphertext": "<base64 CryptoEnvelope v2 bytes>"
}
```

The exact Argon2 values are generated by the platform benchmark and clamped to the accepted backup range:

- operations: 2 through 10
- memory: 32 MiB through 256 MiB
- parallelism: 1 through 8

The backup password is independent of the vault master password. Argon2id derives the backup key from the backup
password and a newly generated 16-byte salt. XChaCha20-Poly1305 encrypts and authenticates the serialized snapshot
with a unique 24-byte nonce and associated data `passvault:backup:v1`.

`ciphertext` contains the project `CryptoEnvelope` v2 marker followed by the authenticated ciphertext. There is no
separate HMAC, wrapped transport key, binary header, compression layer, or plaintext backup type.

## Encrypted payload

After decryption, the payload is strict JSON (`ignoreUnknownKeys = false`) with:

- the single vault-metadata record;
- encrypted credential records;
- encrypted folder and tag records;
- credential/folder and credential/tag relationships;
- encrypted password-history records;
- attachment metadata records; and
- an `attachmentsIncluded` flag.

The database records are already encrypted at the record boundary. The backup envelope independently protects the
complete snapshot with the backup password.

Attachment file bytes are never included in version 1. `attachmentsIncluded` is therefore `false`; existing
encrypted filename metadata may be preserved, and restore preview warns that file bytes are absent. Asking the
service to include attachment files fails explicitly.

## Validation and restore

Before preview or restore, the implementation checks:

- a 128 MiB maximum container size and a 64 MiB maximum decoded payload;
- format, KDF, vault-format, and crypto-format versions;
- exact salt and nonce sizes and bounded Argon2 parameters;
- supported authenticated-encryption envelopes;
- bounded entity counts, identifiers, text, paths, hashes, and attachment sizes;
- unique identifiers and referential integrity;
- folder parent integrity and cycle absence;
- credential, tag, folder, attachment, and password-history references; and
- consistency between the vault metadata entry count and credential rows.

Wrong passwords, tampering, malformed JSON, unsupported versions, invalid base64, and invalid relationships return
the same non-sensitive error. Preview performs all validation without writes.

Restore locks the current vault and replaces all persisted vault tables in one Room transaction. Any parse,
authentication, constraint, or insertion failure leaves the previous database state intact. The direct
`credential_records.folder_id` value is canonical; the legacy redundant cross-reference table is rebuilt from it.
The restored vault remains locked and must be unlocked with the restored vault's master password.

## Platform file handling

- Android uses the Storage Access Framework; common code never resolves arbitrary filesystem paths.
- Desktop uses the native AWT file dialog and writes through a temporary sibling file before replacing the target.
- User cancellation is represented by `BackupFileSelectionCancelled` and is not shown as an error.

## Compatibility policy

Only `formatVersion = 1`, vault formats 1–2, and crypto format 2 are accepted by this implementation. Vault format 2
identifies encrypted credential payloads that may contain TOTP configuration. New versions must add explicit
compatibility code and wrong-password/tamper/truncation/unsupported-version/transaction tests before changing these
constants.

There is no CSV, plaintext export, cloud upload, merge restore, or attachment-file packaging in this release.
