## Smallest meaningful native slice; reject substitute claims

The existing fixed runner already provides the narrow four-case selection:
`nativeRuntimeIs32BitAndLoadsSodium`, `historicalBinaryPasswordVector`,
`historicalTextPasswordVector`, `productionProfilesMatchReferenceVectors`.
It checks `!Process.is64Bit()`, POINTER4 and SIZE_T4 before any KDF. The first
case performs zero KDFs; the two small cases and ops3/ops4 production-profile
case total four KDF calls. Reconcile all exact start/pass identities and terminal
result, not merely shell/Gradle exit or a partial/empty report.

- A32-bit Linux JVM/JNA call, boxed-Int selector test or mock can assess its own
  host/boxing contract, **not** Android's loader/JNI/bionic/ABI/runtime. Neither
  repeated Linux64 tests nor the Android host-test JVM artifact supplies Android32.
- `multiArch=true` / `use32bitAbi=true` is preference, not actual32-bit execution.
  Do not weaken the runtime gate to run on the installed64-only image.
- An admitted x86 Android32 run is a useful smaller control, **not ARM32**.
  ARM32 can in principle be emulated or physical; actual hardware is mandatory only
  for claims that genuinely concern hardware/Keystore/device behavior. Do not
  invent a blanket physical-device prerequisite for these four pure KDF cases.
- Runtime JNA version/sodium mapping are not APK ELF hashes or native jnidispatch
  version proof. Bind actual artifact bytes and ABI, not directory names alone.
