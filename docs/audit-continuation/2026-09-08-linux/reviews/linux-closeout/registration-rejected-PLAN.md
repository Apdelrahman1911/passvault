## Descriptor-bound preflight and removal lifecycle

The helper retains all original parent/top FDs under the original lock. Every
directory component opens no-follow and is checked against its original tuple;
every input uses stable descriptor/name pre/open/post-read identity checks.

After new exact admission, exclusive creation of **E/CLOSEOUT-JOURNAL.jsonl**
consumes this closeout. Its name and parent are fsynced. No other runtime/evidence
output is created. Existing name/partial journal means no replay. An early
pre-journal refusal also grants no automatic retry; root must retain the external
launcher outcome. Do not delete the failed journal or change its namespace.
The initial empty file is checked against its original full descriptor/name pin.
Every later append requires the last completed full pin and length before writing;
after fsync, descriptor/name/original-field/length proof must succeed before state
advances. Interrupted mutation is sticky failure, not evidence normalization.

Before any unlink/rmdir:

1. Preserve/hash/fsync original bounded run/launcher evidence; establish stop and
   fresh settlement/mount/resource gates; verify original source.
2. Snapshot **all33 trees**, including protected report metadata, via fd-relative
   `scandir`, no-follow stat/open and retained stack FDs. Reject unknown/special
   types, symlinks, hardlinks, foreign UID/set-id and unadmitted device. No file
   contents are read to decide deletion; protected report/XML content checks are
   preservation evidence, not deletion authority. Reconcile directory membership
   before/after traversal. Bound the full forest before first deletion.
3. Persist each target's original pin, bounded descendant snapshot digest,
   file/directory/logical/allocated accounting, protected report-root count,
   retained counts/cost and durable `target_deletion_intent`. All33 intents and
   all-tree preflight completion precede the first destructive syscall.
4. Recheck original inputs, evidence, directories, validity and fresh settlement.

Deletion uses only `unlink(name,dir_fd=parent)` / `rmdir(name,dir_fd=parent)`.
Before each syscall, check all retained ancestor/target stack descriptor and
pathname identities, original lock, captured leaf/dir identity, time and monotone
cancellation. Block INT/TERM/HUP for the final identity/pending-signal check and
one destructive commitment; a later signal is latched on unmask and prevents the
next deletion. This is not an atomic inode-conditional kernel deletion primitive.
Unknown/missing/replaced children detected after preflight cause partial HOLD.
Cooperative frozen producers, not hostile same-UID writers, are the admitted model.

Each containing directory is fsynced after its child operations; top parent is
fsynced before a durable `target_outcome`. `REMOVED` requires this helper's actual
authorized top rmdir and completed parent durability, not later absence.
`CLEARED_ALLOWED_MEMBERS_PROTECTED_REPORTS_RETAINED` records a pruned top whose
protected reports/`.git` and required ancestors remain. No whole R/checkout
deletion occurs. Retained graphs/identities and absent removed names are checked
again; source, input/evidence hashes, mounts/resources/process settlement are
revalidated. Final terminal0 means bounded closeout only, never application PASS.

Any exception/cancellation/resource/preservation/mount/process/pin problem stops
further deletion. A durable `terminal_hold` records the phase and observed unlink/
rmdir counts, explicitly **not all parent durability proven** after interruption.
If even evidence persistence fails, the partial journal and external nonzero
receipt are consumed HOLD. There is no automatic retry, recovery, new root
adoption, stop replay or changing an unknown target into a successful removal.
